# 手机背面的 Claude 用量

[English](README.md) · **简体中文**

你的 Claude Code 用量限制，实时显示在 Xiaomi 17 Pro、17 Pro Max、18 Pro 和 18 Pro Max 的背屏上——不用解锁、不用打开任何东西、也不用去问，就能看到当前窗口还剩多少。

![面板在手机背屏上运行](assets/rear-panel.mp4)

两个账号，每个账号三个窗口，外加一个吉祥物，隔着一张桌子扫一眼就能知道状态。

> **登录之前，请先阅读「[请先阅读](#请先阅读)」一节。** 这是一个个人项目，它会处理账号凭据，并代表你调用 API。

---

## 吉祥物

每个账号一个，站在自己的 5 小时进度条上。看它正在演哪一出，不用读任何数字就能知道状态。

### 行走——空闲

![行走](assets/states/walk.png)

**没什么可报告的。** 窗口用量处在中间某处，而你目前也没有在快速消耗它。它沿着自己的进度条从头走到尾，跳回起点，再走一遍——走完一趟需要 **11.5 秒**，而且它永远不会离开自己所属的那根进度条。

### 举重——你正在工作

![举重](assets/states/muscle.png)

**过去十分钟内消耗了 5 小时窗口的 1% 或更多。** 最后一次集中消耗之后，它会把这个姿势保持五分钟，每一次新的集中消耗都会重新开始计时——所以持续工作时它会一直举着，而不是每次轮询都在不同姿势之间来回闪烁。

### 举旗——快用完了

![举旗](assets/states/flag.png)

**5 小时窗口已超过 90%。** 它的优先级被刻意排在举重之上：如果先检查“你是否在工作”，警告就会恰好在最需要它的时刻被掩盖。

### 睡觉——窗口已用尽

![睡觉](assets/states/sleep.png)

**5 小时窗口达到 99% 或以上。** 在窗口滚动到下一个之前已无事可做，于是吉祥物干脆睡过去。它的优先级高于举旗——举旗正是预告这一刻的警告：超过 99% 之后，已没有什么余量需要谨慎使用，警告也就没有了用处。它的优先级同样高于举重——一个已经空了的窗口，不可能还在发生集中消耗。

它和下面的“死亡”姿势不同，而这个区别正是重点所在：这个窗口几个小时后就会恢复，而一周的额度不会。

### 彩带——全新开始

![彩带](assets/states/confetti.png)

**5 小时窗口尚未开始。** 一点没用，一切都在前方。除了一周额度已用尽之外，它的优先级高于一切——包括窗口滚动之前遗留下来、仍在保持中的举重姿势，那个姿势描述的是你在一个已不复存在的窗口上所做的事。

判断条件是窗口“尚未运行”，而不是读数为 0%，这两者并不是一回事。5 小时窗口从第一次使用时开始，所以在你用任何东西之前，根本就不存在窗口。一个已经开始、四舍五入后为 0% 的窗口，是一个已经在走、过去了几分钟的时钟——对它撒彩带，庆祝的是一个其实早已悄悄开始的全新开始。

### 死亡——一周额度没了

![死亡](assets/states/dead.png)

**7 天窗口已用尽**（99% 或以上）。吉祥物侧躺着，眼睛是两个叉。

判断条件特意定在*每周*用量限制上，因为这是你没法靠等来解决的那一个，而且它的优先级高于下面的所有状态。5 小时窗口每五小时恢复一次，所以一旦某个窗口滚动到下一个，你就有了一个全新的会话，而一周的用量仍是 100%——如果没有这条规则，吉祥物就会对一个已经没有任何额度可用的账号撒彩带。

### 幽灵——没人在家

![幽灵](assets/states/ghost.png)

**该账号没有可用的凭据**——从未连接、已退出登录，或者其刷新令牌已过期。灰色、半透明，白色眼睛：没有腿，尾巴由四个方块组成，逐渐变细、淡出，下落时像蛇一样摆动，每一块都比上面那块摆得更宽、更迟，所以尾尖还在赶往头部早已到过的地方。

这是唯一一个不使用账号颜色的姿势。其他每个吉祥物都在报告那个账号的情况；这一个报告的是“没有什么可报告”，而用代表“这是你的”的配色去描述并不存在的数据，就是一个小小的谎言。

它和死亡不是一回事，把两者区分开很重要。死亡是关于用量的事实：一周额度已用尽，数字是真实的，而且全都很糟。幽灵则是数字的*缺席*——没有人应答，也没有什么可报告。在它出现之前，一个已退出登录的账号会继续在 0% 时庆祝，或者在 95% 时挥旗，重放它失去访问权限之前最后看到的读数。

### 谁胜出

多个状态可能同时成立，所以它们有优先级排序。第一个适用的那一行，就是你看到的：

| | 条件 | 为什么排在这里 |
|---|---|---|
| **死亡** | 7 天窗口达到 99% | 这是没法靠等来解决的限制——它下面的一切都不重要 |
| **彩带** | 5 小时窗口尚未开始 | 毫无歧义：根本没有消耗可衡量 |
| **睡觉** | 5 小时窗口达到 99% | 过了这一点，警告已无可警告 |
| **举旗** | 5 小时窗口超过 90% | 即使你仍在消耗它，也会显示 |
| **举重** | 过去十分钟内消耗了 1% | 你正在做的事，前提是上面的都不成立 |
| **行走** | 其他任何情况 | 在中间某处闲逛 |

最上面三个描述的是**你所处的位置**，它们下面的两个描述的是**你正在做什么**，这正是如此排序的全部理由：一个你需要的警告，比一个你自己已经能感觉到的活动更有价值。

## 从未连接的账号不会出现

用量页只显示有凭据的账号。从未登录过的账号，或者你已退出登录的账号，会被完全排除——手动退出登录会清除手机上保存的关于该账号的一切：凭据、套餐、名称、用量历史和最后的数字，因此不会有任何过期的数据再冒出来：只连接一个账号时，面板会居中显示那一个，而不是让一个灰色的 SIGN IN（登录）和一个幽灵占据另一半。会话只是过期了的账号则会保留，显示为带 SIGN IN 的幽灵，因为它曾是你的，并且希望你回来。完全没有连接任何账号时，用量页不会显示：时钟页就是首页，有内容播放时媒体页位于其下方——而且音乐开始时它会自动向上滑入视野，因为时钟页上没有通知条来传达这个消息。镜头周围的圆环在每一页上都保留着它们的玻璃环带，空着，并在下方的媒体页中变成媒体转盘。

## 圆环和进度条

**圆环是直接画在面板上的弧线**——它们背后没有灰色的圆。那个底圈原本是为了表达读数占整体的比例，但在一个围绕两个摄像头镜头绘制的面板上，它表达的主要是“这里有个灰色的圆”：看起来更像硬件，而不像刻度。进度条保留了它们的轨道，因为进度条是列表中的一个矩形，正是底色让这一行清晰可读。

**默认情况下，圆环是时钟，而不是仪表。** 每个圆环显示该账号 5 小时窗口距离重置的剩余时间，与手机实际的摄像头镜头同心绘制。窗口时间流逝时它们逐渐填满，所以满环意味着即将重置——是好消息。这也是它们使用强调色而不是渐变色的原因：从绿到红的渐变表达的意思，会与满环的含义恰好相反。

圆环可以指向另一个窗口，也可以切换为显示**使用率**——这时它*就是*一个仪表，并像进度条一样采用渐变色——或者设置为显示**无**，即清空它。光秃秃的镜头外圈也是一种合理的外观；在 GLASS 下，镜头周围的玻璃环带仍然保留，只是空着。

**只有一个账号时，它独占两个圆环。** 只连接一个账号时，第二个圆环也会报告这个账号的情况，并有自己独立的设置（初始为 5 小时使用率——这样一个圆环可以倒数到重置，另一个则随用量填满）。第二个账号连接后会收回它的圆环，而第二个圆环的这些设置会保留下来，等第一个账号再次独自使用时生效。

**进度条显示的是使用率**，每个窗口一行：

| 行 | 窗口 |
|---|---|
| `ALL 5H` | 5 小时会话限制 |
| `ALL 7D` | 所有模型共用的 7 天限制 |
| `<MODEL> 7D` | 针对特定模型的 7 天限制 |

每根进度条都带有它的百分比，以及该窗口距离重置的时间。随着填满，它们从绿色经琥珀色渐变到红色。

两者都以 1.8s 的缓入缓出动画过渡，而不是直接跳到新值，这样即使你没有刻意盯着，变化也会吸引你的注意——而且绝不会过冲，因为一根冲过 100% 再回落的进度条，报告的是数据里从未有过的数字。

## 面板的两种材质

这里的主题不是简单的换配色。它改变的是字体、图标集和材质，面板上的一切都随之变化。（无论你选哪个，设置应用都是玻璃风格——参见[设置应用](#设置应用)。）

**ORIGINAL** 是面板最初的样子：Departure Mono 字体，从终端字体中描摹成像素矩形的字形，纯色填充，硬朗的边缘。一切都画成一行行矩形，因为面板的所有图形都是这样自己绘制的，而为了渲染四个图形就打包一整套 Nerd Font，会给一个 1.4MB 的版本增加好几 MB。

**GLASS** 使用 Outfit、Material Symbols Rounded 和真实的折射——基于 [AndroidLiquidGlass](https://github.com/Kyant0/AndroidLiquidGlass) 构建，其 AGSL 代码连同许可证一起内置在本项目中。每一个原本是填充形状的表面，都变成一块会弯折其背后面板内容的玻璃面板：通知卡片、解锁滑块、播放控制按钮、扬声器、控制器，以及每根进度条和每个圆环上的滑钮。

透镜效果直接取自参考实现，使用参考实现自己的参数，处于其滑块的滑钮被按住时所达到的状态——因为这些滑钮实际上从来不会被按住。它们是读数，而一个永远看起来像手势做到一半的读数是在撒谎；一个永远看起来处于控件最坚实状态的读数，则恰恰就是这个控件本来的样子。

**清透，绝不磨砂。** 最初透镜下面有一层模糊，那是参考实现对静止状态滑钮的处理方式，而这恰恰是该组件中不该照搬的那一半。模糊是表面无法被看穿时的样子；而这块面板的全部魅力，就在于你能看穿它。

### 玻璃从背后的内容中取色

固定的着色只适用于固定的背景。通知卡片和充电电池格是针对黑色面板调校的；在后面放一张照片，为黑色选定的着色就成了一块污迹，而为照片选定的着色在面板变暗的那一刻就会消失。

所以玻璃面板会读取背景并作出回应——这也是参考实现自己的方法：把背景缩放到二十五个像素，计算它们的 Rec.709 亮度平均值，再据此驱动玻璃。二十五并不是对某个更好答案的近似；一块玻璃面板覆盖的是一个区域，重要的是这个区域的平均值，所以丢掉细节*本身*就是测量。

与参考实现的不同之处：参考实现在一部只运行一个演示的手机上，每帧都从图层回读背景。而这块面板始终开着，每帧回读像素是它能做的最昂贵的事——它会让渲染线程停下来等待 GPU。这些玻璃面板背后是一张背景图和一个底色，两者在帧与帧之间都不会变化，所以只有当其中之一变化时才重建网格。

按钮得到的是反过来的处理。它们按设计完全不带着色，这在面板的大部分区域是对的，在两个极端却是错的：在黑色上，透过它们什么也看不到，圆盘就消失了；在明亮的照片上，它们就成了一个带边的洞。它们*只*在透明玻璃失效的地方获得着色，中间地带则没有。

### 玻璃设置

在 Glass / Original 选项下方，**GLASS SETTINGS**（玻璃设置）会打开一个实验室：你的背景，其下方一条黑、灰、白的色带，三种颜色上各有一块固定的玻璃，另外还有一块可以拖到任意位置——绘制方式与背屏绘制玻璃的方式完全相同。三项设置，背屏上的每一块玻璃面板都会实时跟随它们，包括摄像头周围的圆环：

- **Luminance reactivity**（亮度响应）—— *None*（无）、*Global*（全局：所有玻璃同时响应整个背景的亮度）或 *Shard*（碎片：每块玻璃面板响应其正后方的内容，也就是上文描述的行为）。
- **Tint**（着色）和 **tint intensity**（着色强度）—— 玻璃偏向的颜色，以及偏多少。

### 设置应用

用来设置面板的应用始终是玻璃风格，无论背屏使用哪个主题——主题是背屏的。它的背后是一片流动的丝绸，绿色（#49701D），45°，玻璃会随着丝绸的流动而弯折它；对话框是覆盖在其后方屏幕模糊之上的磨砂玻璃，开关是 AndroidLiquidGlass 组件目录中的液态玻璃开关，颜色是玻璃圆点，强调色是 #E7FF00。

它围绕一个**底部栏**布局——General（通用）、Info（信息）、Usage（用量）、Media（媒体）和 Always-on（息屏显示），用的正是 Kyant 的液态玻璃标签栏本身——每个标签显示各自的设置，并让预览显示这些设置所对应的页面：Info 对应时钟页，Usage 对应用量页，Media 对应媒体页，Always-on 对应昏暗的息屏显示页。切换标签时，设置会横向滑动，就像翻页一样。应用的图标和名称位于预览上方，设置向上滚动时会从预览后方穿过一条使其模糊并淡出的过渡带，而不是停在一条边缘上。

开关、选项、按钮、滑块、颜色块和对话框，都是 AndroidLiquidGlass 组件目录应用中组件的移植，用 View 重新构建，因为该目录应用使用的是 Compose，而本应用不是。下拉菜单变成了分段控件，这正是组件目录中用于做选择的控件。

**字体也由你决定**（General → Font（通用 → 字体））：Outfit、Departure Mono、手机上安装的任何字体，或你导入的字体文件——长按已导入的字体即可删除。

## 背景

背屏可以使用四种背景之一（General → Background（通用 → 背景）），在它们之间切换不会删除任何东西——你的图片和视频连同各自的设置都会保留，随时可以切回去：

- **Color**（颜色）—— 纯色底。
- **Image**（图片）—— 一张照片，在一个按背屏真实比例和圆角取景的编辑器中拖动、捏合，使其适配背屏自身的形状，并可设置不透明度和其后方的颜色。
- **Video**（视频）—— 一段视频片段，以同样的方式取景，在一条缩略图带上剪辑（拖动其手柄即可预览画面），设置不透明度和后方的颜色，然后确认。应用会按背屏的精确尺寸裁出一段自己的小片段（HDR 会转换为普通色彩），旁边再放一份倒放副本用于反向播放，并显示进度；Cancel（取消）会让一切保持原样。四种播放方式：**Linear**（线性：解锁时播放一次，停在最后一帧）、**Yoyo**（溜溜球：面板打开时正放，休眠时倒回开头）、**Loop**（循环）和 **Ping-pong**（往返）。**Ease in**（缓入）和 **Ease out**（缓出）（0 到 2.5 s）让它从慢速逐渐加速，并在每次停下前逐渐减速——包括一次播放的两端，以及每一次休眠、变暗、息屏显示和唤醒——减速的帧会进行混合，让慢动作保持流畅。循环播放的视频在背屏唤醒时会从原来的位置继续播放，即使屏幕曾经关闭过。
- **Shader**（着色器）—— 即设置应用背后的那片丝绸。即将推出；选择它时会提示这一点。

**Tilt parallax**（倾斜视差）和 **scroll parallax**（滚动视差）会在你倾斜手机、以及在页面之间滑动时，让图片、视频或着色器轻微移动。图片以两倍分辨率保存，视频片段在裁剪时会保留一圈真实画面作为余量，所以移动时永远不需要放大它们。

## 想要的话，还有 CRT 屏幕

设置界面上有一个开关，默认关闭，打开后会把面板画得像在一根曲面显像管上：画面向外弯曲，每三个像素一条扫描线，由红、绿、蓝色列组成的荫罩，暗角和色彩边缘——这是 896.ro 上终端的外观，从其着色器移植而来，并为了一臂之外观看的面板加强了效果。它叠加在当前所用的任何主题之上，所以叠加层、滑块和息屏显示也都会经过它。

有三样东西它不会碰。边缘：沿边框的一条带，宽度足以容纳屏幕自身的圆角，弯曲效果在这里逐渐减弱为零——所以边框依然是边框，没有任何角落会变黑。圆环：它们位于玻璃下方的摄像头镜头周围，一旦被弯曲就不再围着镜头了，所以弯曲效果在圆环内部也逐渐减弱为零。还有桌面灯光，它们就是被点亮的边缘：它们画在显像管之上，而不是透过显像管。

被舍弃的部分：网站上的闪烁和噪点。这些需要每隔几毫秒画一个新帧，而这块面板不会画没有理由画的帧（息屏显示中静止的页面不消耗任何资源）。这里保留的效果只取决于画面本身，所以每种尺寸只设置一次，绝不逐帧计算。

显像管在每个点上显示的是稍微更靠外一点的画面，所以触摸在被任何东西读取之前，也会以同样的方式被移动，移动量取决于该处适用的弯曲程度：边缘带和圆环中不移动，画面中部的开阔区域移动最多。编译失败的着色器会被记录到日志，面板保持平面；它绝不会让面板崩溃。

## 预览显示的就是面板显示的内容

正面屏幕上的预览与面板是同一个视图类，绘制同样的配置——但它运行在另一个进程中，而通知和媒体是通过广播送达面板的。预览从未收到这些广播，所以它只显示用量页，你来这里要配置的东西一样也看不到。现在它会监听同样的广播，并在打开时向监听服务询问正在播放什么。

它也是惰性的：上面的任何东西都不能按下或拖动。它位于一个可滚动的设置页面中，所以在此之前，每次拖过它的手势都会被交给面板的翻页器，滚动应用时会悄悄地把预览滚到媒体页上。

它还会镜像背屏自身的状态，而不只是数据：背屏所在的页面、息屏显示、解锁滑块、为休眠而合拢的圆环、桌面灯光以及双击带来的变暗，都会在发生时同步显示在预览上——每当其中之一发生变化，面板就会发布出来，设置界面打开时也会主动询问一次。而且预览会按背屏自身的圆角裁切，半径是面板从其窗口测得的——所以无论在哪部手机上，它都是背屏的形状。

## 正面屏幕上也有

PERSONAL 100% · WORK 38% · ALL 5H resets 9m / 49m

## 面板上的按钮

两个按钮都是开关，而且都**按页面**设置：Usage（用量）标签页里有一对 Camera（相机）和 Game（游戏）按钮，用于用量页的两个角；Info（信息）标签页里则有为时钟页准备的另一对，各自有自己的颜色——所以它们可以只出现在其中一页、两页都出现，或者都不出现。两页上的同一个按钮就是同一个按钮：在两页之间滑动时，它会从一页上的位置移动到另一页上的位置，颜色随之过渡，而不是跟着页面一起滚走。

背屏有**自己的触摸屏**——第二块 904x572 的触控层（digitizer）——所以在背面的点按是真正的点按，而不是从正面转发过来的手势。

### Camera

在背屏上打开系统相机，这样主摄镜头就变成了一个能看到取景画面的自拍相机。所用的组件和标志位都是 MIUI 自己的，是从手动操作一遍时的实时跟踪记录里读出来的；随后相机应用会自行在正面屏幕上调出它自己的配套界面。

**也可以从背面关闭**：点按相机画面左侧那条空着的灰色带。第一次打开时，会有一条提示说明这一点——它带着 Game 按钮的涟漪从相机按钮中展开，覆盖在你自己的背景之上，并用强调色点亮应该点按的位置。

关闭相机后会回到面板。这不是假设——面板、相机覆盖在上、返回、再回到面板，都实测过。关闭也会让相机停止：以前关闭只是把它的取景画面从屏幕上拿掉，相机应用仍在面板后面运行，镜头开着。现在是请求它自行退出，而不是强制停止，区别在于它真的会退出。

### Game

位于左上角，图标是一个手柄而不是叉号。用涟漪把用量页抹去，只留下吉祥物在面板底部走动。点按吉祥物即可让用量页回来。

它在很长一段时间里都是叉号，这如实描述了按钮做了什么，却没说清它通往哪里。用量页后面并不是空无一物——那是吉祥物自己的屏幕，而这个屏幕将来会是可以玩的东西。叉号的意思是「关掉这个」；手柄的意思是「去那里」。目前这个屏幕显示 **COMING SOON**（即将推出），居中于面板上你真正能看到的部分，而不是整个面板：左侧 296 个单位是镜头玻璃，所以按真正的中线居中的文字会有三分之一藏在镜头下面。

它随用量页一起滚走，而不是固定在两页之上。它关闭的是*用量页*，所以在不是用量页的页面上，它就成了一个通往别处的按钮。

只有这个按钮会关闭面板。这听起来理所当然，但事实并非如此：原来的判断是「有没有点中任何东西」，当相机按钮和它是仅有的两个目标时，这没有问题，但此后加入的每个控件都悄悄被算了进去——直到在媒体页音量区域的任意位置点一下，就把整个面板抹掉了。

它原来位于左下角，与图片在同一条线上。之所以挪走，是因为媒体行需要那个角落放封面，而左上角是唯一真正空着的地方：圆环画在屏幕挖孔区域之内，止于 278；标题栏以进度条那一列为中心，即使是允许的最长标题，也到不了 377 的左边。

**这不是关闭面板。** 面板会继续绘制、继续轮询，并保持存活。一个关掉了自己面板的应用无法再把它放回去——放置面板需要 Shizuku 和一个仍然存在的任务——而这正是整个项目从一开始就围绕着要避免的故障。它的做法是安静下来：背景降到很低的透明度（alpha），系统自己的背屏界面透出来。

这个 alpha 永远不为零，代码里用大写字母强调了两次。一旦为零，面板就会完全失效：没有任何东西遮挡时，MIUI 的 SubScreenLauncher 会恢复运行并接管屏幕，本应用的窗口会离开窗口列表，而它的进程和任务记录依然存活——这是重启看门狗看不到的故障，因为它检查的是「**任务**是否存活」，而任务好好的。

涟漪从你触摸的位置向外扩散，而且可以被打断：中途改了主意，它会从中途反向收回，持续时间由剩余的距离决定。

## 面板何时自己点亮

通知或充电器会唤醒背屏，这样在值得一看的东西到来的那一刻，面板就是可读的，而不是等到你下一次碰巧看它的时候。

这就带来一个它必须自己解决的问题：**一部会自己点亮背屏的手机，很多时候是在口袋里。** 这时面板上的每个控件都压在大腿下面——音量条、播放控制、翻页滑动。一块会自己亮起的屏幕，必须假定没有人要求它亮。

所以它拒绝一切操作，改为显示一个滑块。不用点按，因为布料也会「点按」；也不用点按右端，因为那只是多了几步的点按。拇指必须落在旋钮静止的位置——左侧——然后一路拖到另一端，中途不能松开——一个手势里依次完成三件事，这是口袋做不到的。

它只替换图片区域。圆环、进度条和唱片都留在原位继续报告，因为用量页正是屏幕亮起的原因。播放控制按钮和相机按钮会以滑块出现时的同一个动作离开，因为一个用不了的控件不应该摆在那里，看上去像能用。

如果没人滑动，面板会等到通知或充电器消失，让屏幕重新熄灭，再把图片放回去——全程带动画，包括唱片重新转起来。

### 没人看的时候

**双击会让它像小米自己的背屏那样进入休眠**：面板立即变暗并释放屏幕，HyperOS 按照它自己的背屏超时，在点按十秒后关闭屏幕。变暗期间再次双击会取消休眠；单次触摸则不会，所以手指轻轻蹭到也不会把它唤回。HyperOS 默认会自己处理背屏双击，并当场关闭屏幕；面板借助小米自家应用使用的同一个隐藏 MIUI 窗口标志（`MIUI_FLAG_DISABLE_SUBSCREEN_DOUBLE_TAP`，位于窗口的 `miuiFlags` 中，通过隐藏 API 绕过机制设置），让自己的窗口退出这个手势。用力敲击仍然会经过 HyperOS 的敲击传感器——没有任何标志能管到它——并直接关闭屏幕。

**有新版本发布时，应用会告诉你**——它每两小时向 GitLab 查询最新的版本发布，如果比你正在运行的构建更新，就会发出一条通知，附带版本说明和一个 **Download APK**（下载 APK）按钮，在浏览器中打开 APK 的永久地址。应用本身不会下载或安装任何东西。设置界面也会提示：只要已知有更新的版本，界面顶部就会出现一行，显示版本标签和版本说明的前几行，点按即可打开 APK。

**桌面模式**：把手机正面朝下平放，背屏朝上，一秒后面板的边缘会亮起来——四盏灯，颜色与时钟相同（或者用它们自己的颜色：Settings → Table lights（设置 → 桌面灯光）），彼此相隔四分之一圈，拖着尾迹沿屏幕自身的圆角边框飞驰三圈，然后放慢，进入最后四分之一圈，每盏灯都在身后留下点亮的边缘；它们相遇之处，整个边框是一圈均匀的光晕——和玻璃效果一样，是一个 AGSL 着色器。只要手机一直躺在那里，光就静静地保持着，拿起时淡出。重力告诉面板它是平放的；背面的距离传感器告诉它那是桌面还是口袋。

**锁定正面屏幕时，背屏会进入息屏显示**（如果已开启），而不是熄灭。

**Always-on display**（息屏显示）是第三种休息方式。面板不会熄灭，而是停在一个暗淡、静止的页面上：没有任何动画，背景在一秒内淡为黑色，屏幕保持点亮。在上面双击会立即弹出解锁滑块；滑动后完整面板回来，最后一次触摸三十秒后它会再次进入息屏状态。它只会在口袋里休眠，而且只在你要求时才会（Settings → Always-on display → pocket mode（设置 → 息屏显示 → 口袋模式），默认关闭，因为如果背面距离传感器在手中也读成被遮挡，面板就会毫无可见理由地变黑）：背面距离传感器被遮挡片刻后，面板会释放屏幕，由 HyperOS 按自己的超时关闭。在桌上正面朝下时，背面传感器没有被遮挡，所以它保持点亮。任何唤醒——通知、充电器、双击——都会回到息屏显示，照常在上面显示通知卡片和滑块。

最后一次触摸三十秒后背屏会熄灭，除非开启了 **Keep panel awake**（保持面板常亮）。即使开启了，如果是通知唤醒了正在休眠的背屏，而没有人滑动滑块，它也会让背屏重新休眠——凌晨三点的一条消息不会让它一直亮到七点。熄灭不等于变暗：休眠时面板什么都不绘制，不获取读数，也不请求歌词。轮询循环并不是每隔几秒检查一次标志然后继续睡——它挂起在面板自己的信号上，在面板表示自己可见之前根本不会被调度，所以手机在口袋里过一夜，请求次数和唤醒次数都恰好是零。熄灭两小时和熄灭两分钟是一样的。一旦亮起，会立即请求一次读数，而且绝不会比正常节奏更频繁：一分钟看它十次也不会多请求任何东西。

在此之前，帧循环实测占用一个核心的 72%，绘制到一块会丢掉每一帧的屏幕上。如上所述，通知或充电器仍然会唤醒它。

## 控制中心

**从背屏最顶端的边缘向下拉**，在屏幕左半边——摄像头右侧一点——任何页面都可以。后面的面板会随之模糊、变暗，并跟随手指：拉过一半或快速滑动就会打开；不到一半则弹回。在任意位置向上拖动即可关闭。它的内容在下拉到一半时才出现，每一项都沿同一条缓动曲线淡入、向下滑动，并以自身中心放大。在滑块锁定或息屏显示状态下它不会打开，并且在两者之一开始时自行关闭。

- **亮度**——左侧那个充电电池格的玻璃和液体，液面对应 HyperOS 自己的背屏亮度（系统设置 `sub_display_screen_brightness`，1% 到 100%）。在上面上下拖动即可调节。拖动时，百分比会在旁边放大出现，就像充电数字那样，停下两秒后缩小消失；玻璃里的一个太阳随亮度转动，背屏越亮，光芒越长，被液体覆盖的部分则反色显示。新的读数会「倒」进去，而不是直接跳变。
- **A**，在它下面——HyperOS 的背屏自动亮度，依据背面的光线传感器。自动亮度选定某个亮度时，液面随即跟着变化：应用是监听这项设置，而不是去询问它。手动调节亮度会关闭自动亮度。
- **静音、蓝牙、移动数据、Wi-Fi**——右侧四个磁贴，两两排列，彼此之间以及与周围所有元素之间都隔着同一个间距，外侧圆角与屏幕本身的圆角一致。静音即铃声模式，由应用自己设置（通知使用权会同时带来勿扰模式的访问权限）；其他三个通过 Shizuku 实现，没有 Shizuku 时显示为浅色。它们会随手机自身开关的变化而变化。

在 GLASS 主题下，每一项都是一块折射着模糊面板的玻璃面板；在 ORIGINAL 主题下，液体、轮廓和数字都是纯白色，开启的开关会填满白色。

**背屏上的每一次滑动在松手后都会以手指的速度继续**——控制中心、翻页、通知的下拉、被快速滑走的卡片、卡片列表——而不是先停下再重新出发，而且一次快速滑动本身就能决定结果。

## 媒体控制

有内容在播放时，底部区域会变成一个播放器：封面、曲目、艺人和三个按钮——尺寸按在手机背面按得准来设计，而不是为了看清，彼此之间以及与标题之间等距排列。停止播放时，图片会回来。

这一行从面板左侧的内容边缘一直延伸到相机按钮开始的地方，而不是在进度条结束的位置停下。它是并排的三样东西，而进度条那里只有一样；如果与进度条那一列对齐，会留下 80 个单位的空白面板，而曲目标题却在第十三个字符处被截断。相机前面的间距故意比这一行内部的间距更宽：相机会打开另一个应用，而按这一行的节奏排列时，它看起来就像第四个播放控制按钮。那块空间一次只放一样东西——它只有 70 个单位高，两样东西挤在一起，就是两样都小到看不清的东西。

切换是一个滚轮，与通知条转动所用的是同一个：图片从底部落下，同时这一行从顶部升起。播放/暂停图标也是如此，只是小一号——在它自己的格子里，暂停升起、播放落下。这样一来，曲目暂停和控件出现就是同一个动作在两种尺度上的表现，而不是两种互不相关的效果。

**不需要新的权限。** 它使用的是你可能已经为镜像通知授予的通知使用权：Android 会把当前活跃的媒体会话交给持有该权限的应用，这就是为什么传给 `MediaSessionManager.getActiveSessions` 的是通知监听器自己的组件。没有这项授权，这个功能完全不起作用，设置里那一行会在下方注明这一点，而不是假装开关生效了。

它仍然是一个**独立的开关**，默认关闭。原因有两个，第二个才是真正的原因：它会占用一块你可能已经放了自己图片的区域，在别人第一次播放歌曲时悄悄盖住他们的图片，那是图片丢了，而不是新功能来了。同意镜像通知，并不等于同意这个。

### 封面

两种样式，在设置中选择。

**Square**（方形）就是播放器提供的封面，裁切填满，而不是加黑边。

两种样式都有媒体页。一开始媒体页只属于唱片样式，理由是方形封面在过渡中没有什么可以带过去的——这是错的：这一行的缩略图也是一个物体。它只是**移动并缩放**，而不是旋转：从曲目名旁边的角落放大到页面中央，返回时再缩回去。一张会旋转的图片就成了唱片机上的图片，而不是封面。

不过换唱片的动画仍然只属于唱片样式。让一个矩形飞进相机镜头，这种巧思只属于形状像唱片的东西；方形封面换曲目时，就直接变成下一张封面。

**Vinyl**（黑胶）是一张与面板等高的唱片，位于用量页后面——居中于面板上真正是屏幕的那一半，并且下沉到有三分之一超出底边。这是唱机上的一张唱片，而不是屏幕上摆着的一个圆。在这种样式下，这一行里没有缩略图：唱片*本身*就是图片，旁边再放一份同样的封面，就是同一张图出现两次。

花了两次尝试才让它不再像一张 CD——当封面图铺满整张碟片时，看上去就是 CD。唱片是黑色的；它的图案是中间一块拳头大小的标签；其余部分你看到的都是纹路。

现在它是一张唱片的**照片**。以前它是画出来的——一个黑色圆形、三十四道同心描边、一圈边缘和两道光泽弧线——而这就是那种做法的真实极限：它画出的是唱片的示意图。真正让人觉得是*黑胶*的，是光线如何成带状掠过纹路、光泽如何向边缘衰减，而一叠按透明度渐变的圆只能暗示这些，永远无法真正做到。需要说清楚的是，这样做在速度上没有带来任何好处：整个画出来的碟片实测耗时 0.2ms。

碟片不旋转，这是有意为之，而不是遗漏——图像上有一道固定的高光横过，就像灯下的唱片那样，转动它就会把灯也一起转起来。它的做法是**倾斜**，每半秒一次，最多三分之一度。第一次尝试用了五度，看起来像唱片在被摇晃；唱机的那点晃动，是只有停下来你才会注意到的东西。

它的**主轴是一个孔**，是挖出来的，而不是画上去的。以前它是一个用面板背景色填充的圆点，只要面板背景*是*那个颜色，它就和孔没有区别——一旦在后面放一张照片，唱片中间就多了一个颜色不对的扁平小圆片。

它在用量页上是半透明的，在媒体页上是不透明的，在两页之间滚动时逐渐加深。两页对它的要求截然相反：在六条进度条和两个圆环后面，一张不透明的碟片就像在面板上打了个洞；而在媒体页上，半透明的碟片看起来像一张唱片的图片，而不是唱片本身。

标签会转。音乐停止时它立刻停住，这正是重点——它是播放状态的第二种显示，比一个 38 单位的图标能在远得多的地方看清，而这块面板大多是隔着一个房间看的。转速大约是 16rpm 而不是 33，因为真实的转速看起来只是一团模糊。

旋转角度是累加出来的，而不是根据时钟推算的，所以暂停会让它停在原处，而不是在看不见的情况下继续转、恢复播放时跳一下。

### 这一行下方的进度条

这一行下方有一条细线，显示曲目播放到了哪里。放在下方而不是上方：放在上方会让它正好位于最后一条用量进度条下面，而同一列中的一条细横线，恰恰就是那些进度条的样子。

播放位置是**向前推算**的，而不是等来的。播放器只在有变化时才报告位置，所以靠报告驱动的进度条会在整首曲目中一动不动，然后跳一下；实际传过来的是一个位置、取得该位置时的时钟读数以及播放速度，面板由此继续往下数。两个进程读取的是同一个系统运行时间时钟（elapsed-time clock），所以这是精确值，而不是估算。它会考虑播放速度，暂停时停止。

任何没有时长的内容——直播流、电台节目——都完全没有进度条，而不是显示一条永远不准确的空进度条。

这条进度条和唱片机页面上的表盘读取的是**同一个**经过缓动的值，而不是各自计算。它以前直接取位置，这使它成为面板上唯一一个始终正确却从不动的部分：换曲目时它不会退回到新的起点，旧曲目离开后的下一帧它就已经在那里了。它看起来是对的，这恰恰是它在旁边表盘的四轮修改中幸存下来的原因——「主页面上的进度条没问题」是真的，也是线索，因为它之所以没问题，*是因为跳过了那个出了故障的跟随器*。

### 上滑：唱片机

有内容在播放时，面板有**第二页**。从用量页向上滑动，图片移到中央，用量页从它上方离开；向下滑动返回。它会吸附：随意拖动，松手后会落在某一页上。

**两种**封面样式下都可以。这一页起初只属于唱片样式，理由是方形封面在过渡中没有什么可以带过去的，后来证明这是错的：这一行的缩略图也是一个物体，只是它移动并放大，而不是旋转。

图片是唯一不滚动的东西。它在两个位置之间移动——一个物体，两个目的地，中间插值——所以面板是变成了一台唱片机，而不是滑到另一个屏幕。**圆环**是另一个例外，而且它们完全不动：它们与手机实际的摄像头镜头同心绘制，一个移动中的圆环，就是一个明显不在它所环绕的镜头上的圆。它们的做法是**扫动**：翻页时，每个圆环从它显示的用量读数缓动到它显示的音乐读数。

这一页承载了那一行放不下的内容：全尺寸的曲目名和艺人，以及更大的播放控制按钮。没有进度条——播放圆环就是位置，在它下方一百个单位处再放一条横向进度条说同样的事，就是同一个读数出现两次，第二个还在和第一个争谁才是真的。以前沿底部排列的两个时间也随之去掉了：它们是同样的两个数字第三次出现，离它们所属的表盘有五百个单位，现在它们沿着弧线本身的两端弯曲排列。

吸附故意设计得很宽容——一次短促的快速滑动本身就算数，超过三分之一距离的拖动都会确定翻页。这是手机背面一块 904x572 的面板，单手握着操作，没有滚动条，也没有可供判断的边缘；否则就是一个拒绝移动又不给理由的界面。

它是按**页数**构建的，而不是一个两态开关，因为它存在的原因是：这块面板最终要容纳的账号会多到一页放不下。增加第三页只是改一个数字。

### 切换曲目

三种不同的切换方式，因为这是三种不同的情况。

**媒体页上的唱片**通过圆环切换：碟片缩小并移入上方的圆环，下一张从下方的圆环中长出来，中间有片刻唱机是空的。圆环之所以能充当这两端，恰恰是因为那个让它们在其他地方都很别扭的特点——圆环环绕着摄像头镜头，镜头里面没有屏幕，所以缩到圆环大小的碟片是真的*消失*了。

**在换曲目之前打上时间戳**的位置属于上一首曲目，会被忽略。播放器是分阶段交付一首曲目的——正是这种分阶段把错误的封套套到了唱片上——所以第一个带有新标题的报告仍可能带着旧的位置：实测中，一个新标题到来时，时钟上显示三十秒，而这首曲目才刚刚开始，这让表盘先走了六分之一圈才倒回去。并不是每次切歌都会这样，这也是它看起来时有时无的原因。MediaSession 会给每个位置打上取得时的时钟读数，所以这是可以判定的，而不需要猜测。

在切歌的间隙——播放器已经丢下一首、还没开始下一首的那一刻——表盘会**保持不动**，而不是继续推算离开的曲目的位置。那首曲目仍被标记为正在播放，所以对它进行外推会让表盘超过它自己的终点：每次切歌时表盘都会填到 100% 再从那里倒回，这不是回到开头，而是先绕了远路。离开的曲目剩下的只有它最后一次报告的内容；它已经不在播放了。

表盘持续跟随曲目，只有在**读数跳变时才缓动**。小于弧长百分之一的变化算作一次正常走动——目标移动了，而动画计时保持不变，所以表盘精确跟踪目标。任何更大的变化都是拖动进度或切换曲目，会得到完整的缓动。如果不做这个区分，缓入缓出（ease-in-out）会在每一帧重新开始，而缓入缓出的每一段都从零速度开始，表盘就永远积累不起速度：实测曲目播放了十六秒，表盘却停在一度。

曲目结束时，播放表盘会**倒回**，而不是直接跳回：读数在两帧之间从接近满格变成零，直接跳过去的表盘看起来像面板跟丢了位置，而不像一张唱片放完了。

**用量页上的唱片**没有圆环可用，所以改为交叉切换：旧的从底部滑出，新的同时从顶部进入，就像一叠唱片依次送入。

**方形封面**从不交叉。它离开后，下一张从同一侧跟着回来——在用量页上是先下后上，在媒体页上是向右出去再回来。两张图片在半空中擦肩而过，看起来会像洗牌，而不像换曲目。

使用哪一种由页面决定，而不是在两页之间混合：飞进圆环和从底部滑出是两段不同的旅程，处于两者之间的状态哪个都不是。

离开的封面带着离开曲目的封套——它被保存为一张**位图（bitmap）**，在切换开始的那一刻捕获，而不是按路径查找。封面文件只有一个，新曲目会覆盖它，所以按路径请求「离开的曲目的图片」，得到的是此后解码进那个文件的内容：到来的封面。这就是为什么一张正在离开的唱片，最后套上了取代它的那张唱片的封套。
### 歌词

默认关闭，而且是一个**独立**的开关，并不属于 “Media controls”（媒体控制）的一部分——因为这是本应用中唯一会向外发送任何数据的功能。想在手机背面放一个播放按钮的人，并没有因此就同意把自己在听什么告诉陌生人。

开启后，每首新曲目的标题、艺术家、专辑和时长会通过 HTTPS 发送到
[LRCLIB](https://lrclib.net)。无需账号，无需密钥，请求中也不附带任何能识别这台手机或其主人的信息。有三点把代价控制在这个程度：

- 关闭意味着**根本不会构建请求**，而不是构建了再丢弃。
- 每个应答都会缓存，**包括“没有歌词”**——否则纯音乐会成为流量最大的来源，因为它们恰恰是永远得不到可存储应答的曲目。单曲循环的一首歌，永远只泄露一次。
- 缓存以**哈希**命名存放，因此目录列表不会是一份明文的收听记录。关掉开关会**删除**缓存：关闭意味着撤销，而不是“停止收集”。

一次请求会先等待 1.2s，等曲目的描述信息不再变化。元数据是分批到达的，所以新曲目的第一次回调常常带着新标题和*上一首*曲目的时长——而时长既是一段录音身份的一半，也是 LRCLIB 用来匹配的依据。据此行动，等于把一次请求花在一段并不存在的录音上。

在面板上：在 **vinyl**（黑胶）样式下，正在唱的那句沿着唱片内侧的弧线弯曲排布，下一句在外侧变暗等待；每次换句时，外侧那句**向内**移动并变亮，旧的一句下沉并淡出。唱片会让出空间——它的尺寸本来就是根据上方内容推算的，所以歌词占用自己区域的方式与通知完全相同。只接受**同步**歌词；不带时间轴的歌词无法说明正在唱哪一句，而在整首歌期间固定显示某一句歌词，只是看起来像读数的装饰。

整个歌词块作为一个整体淡入淡出——开关打开、滚动到该页、某首曲目原来有词——这与某一句被提升是不同的事件，因此处理方式也不同：提升会移动，因为歌曲往前走是有方向的；出现则没有。

在 **square**（方形）样式下，歌词是**直线**排布的，叠在封面上方——正在唱的一句离封面最近，下一句变暗位于其上方。弯曲是给必须沿着唱片边缘走的文字用的；一张照片没有边缘可循，硬把一行字绕着它弯曲，就是从一个并不存在的形状那里借来的装饰。其余一切都是共用的：同一个区域、同一对歌词行、同样的提升，“离封面更远”在一种样式里意味着更大的半径，在另一种里意味着更高的基线。直线排布的行也获得更多空间，因此比弯曲的行更晚开始缩小。

**通知优先。** 有分组卡片显示时，两者放不下；与其把唱片缩成一个小圆片、周围环绕一圈各自旋转的字母，不如让歌词淡出，等卡片离开后再回来。这条规则是根据歌词要环绕的唱片推导出来的，而不是写成“如果有通知”——任何尺寸变化时，结果都会自行修正。

### 两个拖动控件

媒体页在同一个表面上承载三种手势，靠区域**和**方向共同区分，因此任何一种都不会在另一种进行中被意外触发：

| 手势 | 位置 | 作用 |
|---|---|---|
| 垂直 | 任意位置 | 翻页 |
| 垂直 | 右侧六分之一 | 音量 |
| 水平 | 按钮上方的空白区域 | 播放进度 |

最初它们是反过来的——音量占了整个宽阔区域，进度则什么都没有——这把唯一一个与宽度无关的控件放在了最宽的区域上，却让时间轴无处可拖。

音量是**相对**调节的，从手指落下的位置开始算，并实时生效：你能听到结果，所以无需确认，也无需撤回。它的弧线**向上**填充，底部为静音，扬声器图标随弧线头部移动——向下填充的音量会在声音变大时把扬声器送到最底下。

进度只是**预览**。实时跳转会让播放器在拖动的每一帧都重新缓冲，所以只有表盘和时间在动，松手时才发送一次跳转。按住期间圆环**描边加倍并变灰**：操控它的手指在手机的另一面，看不见，所以圆环必须表明自己正被按住；变灰是因为手指下的读数是一个提议，而不是关于音乐的事实。在区域**外**抬起手指会放弃这次手势——表盘本来就指向真实位置，所以松手本身就是动画。

### 长标题在这里也会滚动

与用量页那一行相同的跑马灯：放得下时居中，放不下时左对齐并滚动。左对齐是因为跑马灯必须从某个固定位置开始——把一行正在移动的文字居中，意味着每一帧都以不同的位置为中心。

### 数值变化时会翻转

标题和艺术家在用量页的那一行上也会以同样的滚轮翻转——过长的一行既会翻转，之后也会滚动。

标题、艺术家和两个时间在变化时会以滚轮翻转——与通知条使用的是同一个滚筒——但只在它们*真正*变化时才翻转。一首曲目结束会同时替换四个字段，其中任何一个在切换前后都可能完全相同：同一张专辑的两首曲目艺术家相同，时长相同的两首曲目总时长相同。把一个值翻转成它自己，是一次声称发生了什么事的闪烁，所以每个字段各自判断。

已播放时间是例外：它在平常的每秒走动时**不**翻转。一秒过去是这里唯一一种意料之中的变化，而每秒转一次的滚轮会成为面板上最分散注意力的东西。只有当数字*跳变*时——一次跳转，或新曲目开始——它才翻转。

### 在此页时收到通知

它**不会**把页面往下推。这里的一切都锚定在面板底部——播放控制按钮是最下面的东西——把页面往下推会把它们推出屏幕，按不到。改为由唱片让出空间：它缩小以适应剩余的空间，文字和按钮完全不动。

**歌词则完全让位**，而不是跟着一起缩小。歌词能占多少空间取决于它环绕的唱片：有分组卡片时唱片会缩到最小尺寸，而绕着一个小圆片弯曲的句子只是一圈各自旋转的字母，算不上一行字。所以歌词会为卡片淡出，卡片离开后再回来——参见[歌词](#歌词)。

用量页离开当前页后，也不再跟随通知条移动。它位于上方整整一个面板高度处，把它往下推会让它的底边重新滑入视野、出现在卡片下面——在第二页的卡片后面露出第一页的一条。

### 圆环变成播放器

这一页上最好的东西不需要任何发明：已经有两个圆环与手机真实的摄像头镜头同心绘制，而在这一页上它们无话可说。于是**上方圆环变成播放进度**，**下方圆环变成音量**——两个表盘，放在两块看起来像表盘的硬件上。

它们不是淡出后被替换。随着你滚动，每个圆环会从它所报告的用量**扫动**到它所报告的音乐信息。交叉淡化是最初的尝试，看起来就像同一位置上有两个圆环——而实际上也确实如此。

播放表盘两端都有标签：**弧线起点处弯曲排布已播放时间**，**终点处是总时长**。它们的数字**逐位**翻转：1:21 变成 1:22 只动一位数字，而不是整个时间。整串翻转会让一秒看起来像换了曲目，对一块用余光瞥看的面板来说，这就是“时间在流逝”和“发生了什么事”的区别。音量标签以同样的方式显示读数——`VOLUME 42%`，每个字符一个滚轮，这样单词充当单位，只有变化了的数字会动。中间什么也没有——那里曾经有一阵子放着剩余时间计数器，那是同一个事实的第三种表达，因为弧线已经以形状显示了剩下的部分。页面底部也没有时间；那又是同样的两个数字，离它们所属的表盘有五百个单位远。

弯曲的标签是用叠在填充上的描边**加粗**的，而不是用粗体字重，因为根本没有粗体字重——Departure Mono 只提供一种字形。它们是面板上最细的文字，被弯曲、经过抗锯齿，又压在显示屏最边缘的镜头玻璃上，这是文字所能处的最不利的位置；它们是这里唯一得到这种处理的文字。

每个标签都位于其圆环的**外侧**，这是约束而非偏好：圆环与摄像头镜头同心绘制，而镜头填满了中间的孔。圆环内部没有显示屏——放在那里的任何东西都会完美地渲染进帧缓冲区，然后落在一块玻璃上。

空间很紧张。两个圆环相距 276，半径 128，描边 25，所以它们之间大约只有二十个单位的面板，而下方圆环顶部的外侧就是上方圆环的*内侧*。因此标签被放在有空间的地方，而不是看起来最整齐的地方。播放弧线的两端朝向也相反：文字垂直于其路径站立，所以在上半圈顶部朝外读起来是正的，在下半圈则是顶部朝内。

每段弧线的两端都用一条**从圆环径直向外伸出的细线**标记，颜色与弧线本身相同。背后没有底槽时，静音的音量什么也不显示，而一个在零位找不到的控件，就是一个没法调大的控件。

播放弧线**转动了半个钟点**，为这些标签腾出空间——它从十一点而不是十点半开始，在五点半而不是五点结束，长度不变。标签留在原处，所以这次转动打开的是每个标签与其自身标记之间的角度间隙。

转动表盘是正确的调整方向。最初尝试的是把整个圆环横向平移：空间是腾出来了，但它移动了一个与摄像头镜头同心绘制的圆环，而这恰恰是这些圆环唯一不能动的东西。标签也无处可*移*——上方圆环外侧的对角线方向只有 63 个单位的面板，一个标记加一个标签就要占去大部分。

任何附着在圆环上的东西都在**圆环的坐标系**中绘制，并在其周围抵消防烧屏漂移。圆环是面板上唯一刻意不漂移的东西——它们描绘的是摄像头镜头，必须始终停在镜头上——而其他一切都随着一个以十分钟为周期、游走几个单位的平移而移动。因此在页面坐标系中绘制的标记和标签，一直相对于一个从不移动的圆环滑动：有时与之分开，有时与之接触，有时与之重叠，而且从不重样。这就是“有些对齐了，有些没对齐”的真相。

垂直，仅此而已。如果*沿着*圆环绘制，标记就是与读数同一个圆上的一段弧，颜色也相同——一眼看去与一小段已填充的弧无法区分。横穿刻度而不是躺在刻度上，一直以来都是表盘上标记的样子。

两者都是**仪表弧而不是整圆**，缺口彼此相对：播放从十一点绕到五点半，音量从一点半到四点半。两者都从最初的位置往回转过——播放弧线是为了给标签打开角度间隙，音量弧线则是因为五点钟方向是一块 572 高的面板的右下角，而那个圆环的圆心位于向下 420 处，弧线末端和随之移动的扬声器都被挤到了边缘。两个开口相对的表盘读起来是一对；两个闭合的圆读起来则是两个画了圈的镜头。播放圆环底部的缺口也正是它自己的标签所在的位置。一个扬声器随那段弧线的头部移动并随之转动，因此这个图标是弧线的指针，而不是停在旁边的图例——它所在的位置*就是*数值。

音量弧线**向上**填充：在其所在段的底部为静音，顶部最响。最初是反过来的，而扬声器正是那样做是错的原因——向下填充的音量会在音乐变响时把自己的指针送到底部，与以往画过的所有音量控件相反，也与设置它的拖动方向相反。

那个扬声器以原始尺寸的**一倍半**绘制，与圆环的间距前后调整了三轮，并且会在到达弧线的静音端之前**停下**，而不是一路跟到底：下方圆环的圆心位于 572 高面板的向下 420 处，所以超过某个角度后，这么大的图标会有一半落到底边之外。这个界限是根据各个尺寸推算出来的，而不是写死成一个角度，因此任何尺寸变化时它都会自行修正。注意图标是以其轨道为*中心*放置的，所以它一半的高度也要从间隙中扣除——漏掉这一点，正是曾经让一个标称为十的间隙看起来贴在圆环上的原因。

在 GLASS 下，扬声器和其他所有点击后会做些什么的控件一样，坐在一块玻璃圆片上——它曾是最后一个仍画成裸标记的控件，看起来像圆环的标签，而不是可以按的东西。**气泡容纳着声音**：它的大小取决于最外层声波传播了多远，所以声波离开喇叭口时它张开，声波收回时它闭合。大小*恰好*容纳声波时，看起来像一个勉强撑住东西的气泡，所以覆盖范围做成了曲线——声音传得最近时留出的空间最多，满音量时完全不留——这也让玻璃在其间每一点上都领先于声波。

### 调节音量

在**右侧六分之一的条带内垂直拖动**——这一页上的三种手势如何互不干扰，参见[两个拖动控件](#两个拖动控件)。那正是这款手机正面音量键所在的位置，方向也相同：向上为更响，这也是弧线填充的方向。

它是**相对**调节的，从音量原本所在的位置开始，开发过程中两种方式都试过。绝对式的条带有两端——静音和最大音量变成了位置，而不是要移动的距离——这听起来比实际用起来要好：它把每一次触摸都变成对某个音量的承诺，而且是在一个没人在看的表面上。相对意味着手势是“更响”和“更轻”，一次误触什么也不会做。

在播放进度需要一个拖动的地方之前，它占据着按钮上方的整个区域，并使用横向拖动。那种布局把页面上最宽的区域给了唯一一个与宽度无关的控件。

每调一级都有一次**触感反馈**，所以无需看一块背对着你的屏幕也能调节。反馈落在级数上，而不是落在移动上；每帧振动一次就成了一阵嗒嗒乱响。而且手指按住时圆环以**线性**方式移动，不加缓动：缓动的存在是为了让跳变的数值读起来像一次移动，而一个已经在被手动移动的数值不会跳变——平滑它只会让圆环落后于拖动它的手指。

**静音**是一个紧凑的按钮，就在开孔外侧，跟随扬声器的高度。它不能*就是*扬声器本身：下方圆环画在镜头玻璃上，背后没有触控层，所以弧线把图标带到的任何地方都是手指够不到的地方。它曾短暂地做成音量区域内任意位置点击即静音，这意味着页面三分之二面积上的每一次误触都会让音乐静音。

**静音不等于调到最低**：静音的音频流保留着一个之后会恢复的音量，而音量为零的音频流已经丢失了那个数值。两者都显示一个光秃秃的扬声器；静音时再加一道斜线穿过它。这里使用的是 Android 自带的静音，而不是把音量归零并在某个字段里记住旧值，所以手机和面板在两个方向上都保持一致。

### 按钮先等一等，再相信播放器

按下下一首，播放器会在几百毫秒内报告三个状态：旧曲目停止，加载新曲目时的间隙，然后开始播放。对每一个状态都做出反应，会让播放/暂停图标在每次切歌时闪成播放再闪回来。

所以一次报告不是定论。一个状态必须保持半秒不变才算数，在这个时间窗口内又恢复的状态则永远不算——**除非是面板自己请求的**。与刚刚发出的命令相符的报告是证据，因为播放器是在回答这块面板向它提出的问题，所以按下播放或暂停会立即显示。怀疑只留给那些不请自来的报告。

切歌有一个更长的保护期，从面板发送下一首或上一首时开始，而不是根据标题变化推断出来。推断有一个漏洞：一次丢掉了会话的切歌不会产生可供比较的新标题，而等曲目回来时，已经没有可以与之比较的旧标题了。代价是坦诚的：一次真正的暂停要半秒才会显示。那时按钮已经按下了，一个从容回应的按钮胜过一个在手指下抽搐的按钮。

同样的规则也守护着**是否有东西在播放**，而且必须如此。切歌并不是把一首曲目交接给下一首：播放器在加载时会丢掉会话，所以一个由每次报告驱动的行会在每次按下一首时拆掉自己再重建——唱片从底部滑出又爬回来，而在媒体页上整个页面会消失再回来。在时间窗口内恢复的间隙永远不会被报告。没有恢复的则是真正的停止，这时唱片才会正式离开：它向下滑出面板；如果你正停在媒体页上，面板会自己走回用量页，而不是直接切过去。

### 长标题会滚动

放不进栏宽的曲目标题不会被截断——它会滚动，第二份副本隔着一段间隙跟在后面，所以这一行永远不会倒回，也永远不会空白。它在每一圈开始时会停顿片刻，因为一出现就开始移动的一行文字，你得等上一整圈才能从头读起。

这与通知条的做法相反，是有意为之。通知条只显示五秒，开头几个词就是全部意义所在，所以它使用省略号。一首曲目要播放好几分钟；有时间显示剩下的部分，所以剩下的部分就显示出来。

### 封面，以及它为什么总是慢一拍

封面被写入一个文件并以路径传递，而这个文件的缓存键花了三次尝试才做对。

播放器不会一次性交付一首曲目：**标题和艺术家先到，封面图在之后的回调中才到**。以曲目作为缓存键，意味着较早的回调把*旧*图片写在了*新*曲目的名下，而带着正确图片的回调随后被当作重复而忽略——封面始终正好慢一张专辑。

以封面的 URI 作为键看起来像是修复，其实是同一个 bug 往下挪了一层：URI 也是元数据，它会随标题一起更新，而旁边的位图仍是上一首曲目的。现在的键标识的是**正在写入的字节**——位图用它自己的 generation id，来自 URI 的封面用那个 URI——所以不可能出现键是新的而图片是旧的。

### 什么会传到面板

文本，以及一个小文件。标题、艺术家，以及是否在播放。封面缩放到 140px，写入应用自己的存储，并以**路径**传递——广播中的位图会经由 binder 复制，而 binder 有一个大约一兆字节的硬上限，由所有其他进行中的事务共享。它先写入临时文件再重命名，因为面板此刻可能正在解码上一张，而原子重命名不可能被撞见写到一半的状态。

按钮的方向则反过来。面板没有自己的媒体会话——`MediaController` 属于获取它的那个进程，而 `:rear` 不持有通知使用权——所以一次按下就是一条发回主进程的广播，由持有 controller 的主进程处理。发出的过程中不做任何猜测：面板不会乐观地自行切换图标，而是等播放器说出发生了什么。一个拒绝开始播放的播放按钮，不应该看起来像暂停按钮。

### 如果有多个东西在播放

取系统排序最靠前的那个。不做合并：一个浏览器标签页和一小时前暂停的播客都可能持有会话，而一个显示最先应答者的行会在你手下来回切换。

没有标题的会话会被忽略——抢占了音频焦点的游戏、带有 video 元素的网页——因为一个空行比它替换掉的封面图更糟。
## 来自其他应用的通知

面板可以镜像显示你的其他通知。这需要**通知使用权**，须在系统设置中手动授予——引导列表里有对应的按钮，授予完成后该步骤会自动打勾。

一条通知到来时，一张卡片从顶部滑下，覆盖面板的四分之一，并把用量页一同往下推。**圆环不会移动**：它们与手机实际的镜头同心绘制，挪动它们会让两个圆偏离它们所描摹的硬件一百像素。卡片停留五秒，然后收回。

如果在此之前又来了一条，两条会在一个**滚轮**上交换位置——新的从顶部进入，旧的从底部离开，就像窗口后面转动的鼓。把离开的那条沿来路送回上方，看起来会像是“已取消”；继续向下，则说明下一条已经到了。

### 分组

能产生多条相关通知的应用，会逐条发送每一条，**同时**再发一条代表全部的摘要——WhatsApp 先发出消息，片刻之后再发出 “2 messages from 2 chats”。两者都是真实的通知，以前，后到的摘要会在真正的消息出现后一瞬间就把它替换掉。

现在摘要会被丢弃，改为显示整个分组：最新的消息作为主卡片，下一条以一张较小的卡片附在下方，左侧向内收进一级。这张卡片跟随主卡片进入、先于它离开，因此看起来是第一张的延续，而不是同一个物体在改变大小。

两张卡片都没有边框。它们原本带有一条细线描边，颜色是通知颜色的十分之一，同时把两件事都做得很差：把卡片与面板分开——不透明的底色已经做到了；把两张卡片彼此分开——两者之间的台阶已经做到了。这是在一个只有两条边的形状上多加了第三条边。

用来表明哪张卡片在前面的，改成了**阴影**。两张卡片颜色相同，所以它们的接缝看起来像一个带台阶的形状，而不是一张纸叠在另一张纸上；现在第二张卡片从顶边开始带一道渐变，到自身高度的一半处消失。再往下延伸，它就不再像纵深，而像一张更暗的卡片——只有在能看到渐变在哪里结束时，它才能被读成阴影。

第二张卡片**比它所显示的那条区域更高**，并且位于主卡片*后面*：向上收进一个完整的圆角半径，内容也向下留出同样的内边距——所以可见的部分没有任何移动，而它方形的上角被藏了起来。否则，两张宽度相近的卡片会在一道接缝处相接：主卡片的左下角弯了过去，下方的卡片却没有，眼睛会把下面那张读成被裁掉一截的上面那张，而不是第二张卡片。左侧的台阶由圆角半径推算而来，而不是固定值，因此在任何屏幕上都能避开那段弧线，而不是靠两个单位的运气避开。

来自**另一个**应用的通知没有同组的兄弟，所以第二张卡片会在同一次转动中收起。

同样会被过滤掉的还有以下这些，它们都不算新消息：持续性通知和不可清除的通知、应用声明为 `SERVICE`、`PROGRESS` 或 `TRANSPORT` 的任何通知、本应用自己的通知，以及与已在显示的内容重复的任何通知。最后一项比听起来更重要——一次发布会送达**两次**，相隔几毫秒，因为系统会在排序变化时重新投递。

### 显示什么，不显示什么

| | |
|---|---|
| **始终** | 应用名称、图标，以及通知标题。 |
| **仅在你要求时** | 消息正文。它与该功能本身是**两个独立的开关**。 |
| **从不** | 操作按钮、图片，以及通知中的其他任何内容。 |

中间那一行的理由值得直白地说出来：**这块屏幕背对着你**。上面的一切都是展示给你身后的人看的，而不是给你看的。知道有消息到了，和把消息内容广播出去，是两个不同的决定，所以它们是两个不同的开关，并且默认都是关闭的。关闭正文时，分组的级联会列出**发送者**，而不是一片沉默——面板仍然会告诉你谁在等你。

## 用量页上方的页面

从用量页向上滚动——媒体页在它下方，这一页在上方——面板会滑到一个显示时间的页面。不是淡入淡出，而是滑动，和用量页一样，因此这些页面是叠放在屏幕上的不同事物，而不是同一事物的不同状态。时钟带秒，每一位数字都像滚轮选择器那样独立翻动，所以走过一秒只是一个数字在滚动，而不是整个时钟在重绘。在 GLASS 下，数字由玻璃制成，和充电百分比一样；日期完整拼写——`Thursday, September 3rd, 2026`——外面包着一层玻璃壳，两者都采用用量页自身的时钟和日期所用的颜色。在 ORIGINAL 下，它们是原版描摹的字形。日期下方，只要有读数可显示，就是天气——参见[外面实际是什么天气](#外面实际是什么天气)。

**通知在你下拉之前是隐藏的**：在这一页向下滑动会把它们从上方拉进来，在卡片上向上滑动会把它们收回去，再向上滑动一次则前往用量页——这是这一页的又一步，而不是单独的一页。离开这一页会再次隐藏它们。隐藏期间，新通知会像在其他任何页面上一样，显示在这里的通知条上。

时钟下方是**最近十条通知**，排在一个滚轮上。当前那条完整地位于最前方；相邻的卡片位于它后方半张卡片处，更小、更淡，滚轮停在某张卡片上的方式，与翻页器停在某一页上的方式一样。这十条会被保留，所以凌晨三点唤醒面板的那条消息，七点你去看时仍然在——屏幕为它亮起又熄灭，但通知并没有随之离开。在 ORIGINAL 下，卡片是原版的不透明卡片；在 GLASS 下，它们与通知条所用的玻璃卡片相同，每张都会读取自己在滚轮上所处位置背后的面板。

**向右滑动卡片即可将其移除**。它会以被快速滑动时的速度滑出，周围的卡片顺势滑入空位；如果它还显示在上方的通知条中，也会一并消失。列表为空时，会在一条从黑色渐变出来的色带上显示 *No notifications*（暂无通知），第一张卡片到来时这条色带会滑走。

**Match the front notifications**（与正面通知同步），位于 General（通用）→ Notifications（通知）：每张卡片都记得自己来自哪条通知，所以在正面被清除的通知——被滑走、被点开、被清除、被其应用撤回——也会从背面离开；在背面移除的通知会在正面被清除；每当中继连接上时，背面会丢弃在此期间已从正面离开的所有通知。应用更新一条通知时，会替换它的卡片，而不是再添加一张。

通知下方的那行小字是其分组的摘要——WhatsApp 的 “3 messages from 2 chats”——而不是一条冒充相关通知的旧通知。唱片机会沉到这一页的底部，给卡片腾出空间。

## 充电

给手机插上电源，一个电池格会从右边缘滑入，并被液体填满。

它是液体而不是进度条，这花了三次尝试才做对。水滴是第二次，元球（metaballs）是第三次，两者都是方向错误的答案：团块融合又分开，是液体在*空气*中运动时的样子，而这里是一个盛着液体的容器。无论一堆圆排得多紧密，眼睛总能找到那些疙瘩——因为杯中静止的液体根本没有疙瘩。

它有的是一个**液面**：一条平滑的线，受到扰动时泛起涟漪，放着不管时就恢复平静。电量每经过一个十分位，液面就被敲一下，所以涌入的电量会搅动水面，而不是在一层玻璃下面悄悄往上滑。正在充入的电量以云的方式显现——从内部被照亮，光源始终看不见。

**它知道哪边是下**。液面由重力传感器计算得出，所以把手机翻过来，水面会倾斜。绘制的方向有意滞后于测量的方向：完全跟随传感器会让一次旋转变成瞬移，而让方向转过来，意味着液面会经过中间的每一个角度倾斜——液体是绕着杯壁流过去，而不是在别处重新出现。

在 GLASS 下，电池格是一只真正的玻璃杯：用量页和唱片机会透过水线以上的空白部分发生弯折，而且**液体会放大**。这正是里面装着东西的证据——电池格背后的东西在穿过液面时会错开一截。发生这种情况时，沿弯月面的那条亮线就会去掉，因为放大效果已经说明了液面在哪里，两者叠在一起，看起来会像相距一丝的两个顶面。

百分比位于电池格旁边，与水位同高，并随水位上升，所以这个数字是贴*在*水位上的标签，而不是放在附近的一个数。它与绘制液面所用的是同一个填充量，因此读数和画面不可能不一致。它按电池格自身的时序放大出现、缩小消失——淡入的数字本来就在那里，只是变得可见了；放大出现的数字则是被带来的。

在 GLASS 下，它同样由玻璃制成，使用该字体最粗的字重，并带有一层你为液体所选颜色的薄染。这层薄染的不透明度是五分之一，不能更多：强度再高，着色就成了你看到的主体，下面的折射会被平均成一片纯色，那是彩色文字，而不是着色玻璃。

## 玻璃上的天气

一个设置项——**None, Auto, Rain, Storm or Snow**（无、自动、雨、雷雨、雪）——会在所有内容背后的底层绘制天气：画在颜色或图片之上，而不在任何东西之前，因此用量页保持可读，而卡片会把天气连同背后的其他一切一起折射弯曲。

**雨是水，不是贴图**。水滴以位移的方式绘制：它先弯折下面的内容，然后才获得一道亮边，因为眼睛远在注意到高光之前，就能认出一枚透镜。水滴会附着、流淌，碰到东西时会横向游移，在打滑处放慢，按自身的间距在身后留下小水珠和一道停留几秒的水痕，并沿途把冷凝雾气擦干净，这些地方大约三秒后重新起雾。沿一个单元格每一次流下的都是一滴不同的水滴——不同的起点、不同的路线、不同的速度——因为一个永远流着同一滴水的单元格看起来就像循环播放的视频，而它确实就是。它们按表面的朝向受光，所以没有两滴看起来一样；一滴流动的水滴会吞并它经过的较小水滴，并因此稍稍变大。而且水会绕开摄像头。水滴自己做不到这一点，因为它存在于一个比镜头还窄的单元格里；所以面板沿着穿过两个镜头中心的直线，在每一行按镜头外圈的宽度折叠，各列在其周围分开，于是一道笔直的下落在屏幕上呈现为一条贴着圆环的曲线。水痕和被擦过的路径也随之一致，因为它们沿同一路线绘制。

水滴和雪花以正方形单位布局——面板的高度为 1——所以它们是圆的；若按面板自身在两个方向上各为 0 到 1 的坐标布局，每一个的宽度都会是高度的 1.5 倍。静止的水滴以自身大小完整落下，然后向内干涸直至消失。

**Storm 就是带闪电的雨**：大约每七秒一次，从不卡在固定节拍上，一道闪电会把光线*相乘*——亮的地方闪耀，暗的地方仍然暗——伴随快速、游移的闪烁，在两次闪光之间会略微低于平常的亮度，水滴和雾气也随之闪亮。效果参照 rocksdanister 的 *Rain* 壁纸，用的是本应用自己的数学。遇到雷暴时，**Auto** 会绘制 Storm。

**雪是干的**。雪花落在玻璃上而不会把它打湿，所以它不弯折任何东西——会折射的雪看起来就像忘了怎么下落的雨。它改编自 Lumine 的多层降雪：菱形雪花、每层倾斜角度各不相同的下落，以及一个缓慢漂移的焦深，让清晰的平面在雪中穿行。用十四层，而不是它的四十层——那是桌面级的预算。

雨比雪更耗资源，因为它要折射，而折射是一次依赖读取，GPU 无法预取；在各三层的条件下测量，雪每帧 1 毫秒，雨每帧 16 毫秒，所以雨少用一层。两者下面都没有模糊：降采样模糊出现了块状，已被移除，而弯折本身就足以撑起整个错觉。有一段时间冷凝雾气上出现了矩形，为此追查过六种解释——分块、效果本身、噪声、合成——结果是水场里缺了一项：清除逻辑知道一个像素在水滴*上方*多远，却完全不知道它在侧面多远。

### 外面实际是什么天气

用量页上方的页面在日期下方带有第二个读数：天气状况的图标，然后是 `20° · Overcast`——整数度的温度、一个中点，以及描述天空的词。用整数度，是因为在一块隔着房间读的面板上，十分之一度是一个无话可说的数字。

读数对应的地点放在**下面**，单独一行，居中，更小也更暗。它起初是读数末尾的后缀，字号 11 个单位，在笔记本电脑上清晰可读，在它实际显示的这块面板上却无法辨认；16 是这一页上说明文字已有的字号——即通知正文的字号——而第二行有放下它的空间。在 GLASS 下，两行共用**一张**玻璃卡片，按较宽的那一行裁切，因为它们是同一个读数加上标注在下方的来源，而不是两件挨在一起的东西；温度的数字是与时钟一样的玻璃数字，旁边的文字在两种主题下都是普通字体。在 ORIGINAL 下，整行都是平面文字，配一个用与这里其他所有图标相同的终端字体描摹出的字形。

那张卡片会向下伸入解锁滑块所在的区域，所以**面板锁定时整个区块会离开**，解锁时再回来——这与底部图案和锁定之间的约定相同，而[当面板自己亮起时](#面板何时自己点亮)解释了滑块为什么会存在。时钟和日期不会上移腾出位置：这一页上什么都不移动，所以是淡出，而不是重新排列。离开途中唯一变化的是温度，它在这段过程中退回普通字体——玻璃数字是一种折射而非墨迹，让它淡出，它就是不淡，只会把数字以全强度留在一张空卡片上方。

天气状况采用 Open-Meteo 的 WMO 代码，归并为十种读数和八个图标：晴——白天是太阳，夜晚是月亮——局部多云、阴、雾、毛毛雨、雨、阵雨、雪和雷暴，其中三种下雨天共用一个字形，因为它们是同一幅画面。超出文档所列范围的代码显示为阴，这是对一片无法读出的天空最不算错的说法。这些图标出自与面板上其他所有字形相同的两个生成器：GLASS 下为 Material Symbols Rounded，ORIGINAL 下为描摹的矩形。

读数*对应*哪里，由两个设置和一条规则决定。**Place**（地点）只输入一次、只解析一次——在最后一次按键 800ms 后询问地理编码服务，它返回的坐标就是此后每次轮询所用的坐标，因此不会按计划反复查询。输入框下方的提示会说明它如何理解你输入的内容，即 `Weather for Bucharest, Romania` 或 `Not found`，并在旁边附上 Open-Meteo 的署名；这样，输错的字会在出错的地方显现出来，而不是表现为手机背面少了点什么。另一个设置是 **Use the phone's location**（使用手机位置），只有在你打开它时才会请求粗略位置权限，如果你拒绝，它会自己关回去——一个在没有权限的情况下保持打开的开关，所描述的会是一次早已悄悄退回到所输入地点的获取。

打开该开关后，读数对应手机所在的任何地方，而规则就是下方那一行显示的内容：没有输入任何地点时显示 `Here`，输入了地点时则什么都不显示。该服务能为一个坐标给出读数，却不会为它命名；而在两国之外测得的读数下面印出所输入的地点，就是用小字撒谎。如果定位始终没有到来，会退回到所输入的地点，那一行也就可以重新写出它的名字。

每五分钟一个读数，并且只在面板亮着时。这个循环停在与用量轮询相同的信号上——参见[当没人在看时](#没人看的时候)——所以放在口袋里的手机什么也不请求，而面板一亮就立即请求。设置地点或打开位置开关会缩短等待，而不是让那一行错上五分钟；在面板熄屏时所做的更改，由唤醒时本就会获取的那次读数来响应，而不是在它之后再追加一次。获取失败时会保留上一次读数，因为过时的事实胜过一行空白——但只到一定程度：超过**两小时**的读数会被丢弃而不再显示，无论是那一行还是 Auto 都是如此。两小时前的天空是伪装成事实的猜测。

**Auto** 是 Weather（天气）一行的第二个选项，它把选择交给真实天气：雨、毛毛雨和阵雨带来雨，雷暴带来雷雨，雪带来雪，其他一切都让玻璃面板保持干燥。没有读数、或读数已过期时，它什么都不画——对天空的猜测比干燥的玻璃更糟。它是五个选项中唯一能自己关闭的，这就是全部区别所在：None、Rain、Storm 和 Snow 是关于面板的决定，Auto 是关于天气的决定。

在调试构建中，演示模式自带一个读数——`Somewhere` 的固定 12° 雨天——所以那一行和雨都会出现在录制的循环中，背后无需任何网络。

## 自定义

面板上几乎所有内容都可以编辑，设置界面顶部固定着一个**真实面板的实时预览**——不是仿制的样稿。它是同一个视图在同样 904x572 下的真实实例，只是缩小了，所以它会动，也不可能与手机背面正在显示的内容出现偏差。

| | |
|---|---|
| **Titles**（标题） | 刊头——默认为 `CLAUDE USAGE`——以及每个账号的名称。全部为自由文本；刊头是一个标签，不是品牌标志。每一项的长度上限都是它实际能画出的长度，按真实字体测量而非估算，每个输入框都会标明自己的上限。 |
| **Colours**（颜色） | 每个元素都有自己的颜色，设置在它所绘制的那一项所在的行上，而不是放在别处的一个网格里：刊头、背景、时钟、日期、天气行、电池、相机和游戏按钮（按页面分别设置）、通知文字（以及在 ORIGINAL 下的通知底色），还有媒体页上的播放进度环、音量环、按钮、标题、艺术家和歌词。此外还有每个账号的**强调色**，同时驱动该账号的圆环、标题、行标签和套餐标签；每个吉祥物的身体颜色和硬件颜色分别设置；以及从温和到耗尽的渐变色阶节点。（幽灵是唯一的例外——见上文。） |
| **Layout**（布局） | 每个账号显示哪些进度条行及其顺序、是否显示吉祥物，以及每个圆环报告什么——哪个窗口，显示距重置的时间、使用率，还是什么都不显示。只有一个账号时，它独占两个圆环，每个圆环单独设置。 |
| **Account order**（账号顺序） | 重新排列账号，圆环会随之变化：第一个圆环属于排在首位的账号，所以没有什么需要手动保持同步的。 |
| **Bottom artwork**（底部图案） | 用你自己的图片替换内置标志，在其区域内拖动和双指缩放来定位——由你选择裁切，参照的是一个按该区域真实形状绘制的框。 |
| **Background**（背景） | Color（纯色）、Image（图片）、Video（视频）或 Shader（着色器）——参见[背景](#背景)——带倾斜和滚动视差。 |
| **Time, date, battery**（时间、日期、电池） | 有两套：Info（信息）标签页的用于时钟页（大时钟、日期行、时钟上方的电池），Usage（用量）标签页的用于用量页角落那一行——每项都有自己的开关和颜色。 |
| **Camera, game**（相机、游戏） | 按页面分别设置，位于 Info 和 Usage 标签页——参见[面板上的按钮](#面板上的按钮)。 |
| **Theme**（主题） | ORIGINAL 或 GLASS——背面的外观、字形和材质。它排在列表第一位，因为它是唯一一个会改变其他所有设置外观的设置。在 GLASS 下，**Glass settings**（玻璃设置）用于调节玻璃。 |
| **Font**（字体） | Outfit、Departure Mono、手机上的某个字体，或导入的文件。 |
| **Notifications**（通知） | 开或关、消息文字、其颜色，以及 **match the front notifications**。 |
| **Weather**（天气） | None、Auto、Rain、Storm 或 Snow，绘制在所有内容背后的底层。Auto 会绘制读数所对应地点实际正在下的东西；天空干燥或没有读数时，什么都不画。 |
| **Weather line**（天气行） | 读数本身，位于用量页上方那一页的日期下方。只有色板，没有开关：只要有读数，这一行就在，而下面两行决定是否有读数。在被赋予自己的颜色之前，它沿用日期的颜色。 |
| **Place**（地点） | 天气对应的地点。只输入一次、只解析一次，输入框下方的提示会显示地理编码服务对它的理解——或 `Not found`。 |
| **Use the phone's location**（使用手机位置） | 读数改为跟随手机，使用粗略位置，只有在你打开此项时才会请求。拒绝授权提示，开关就会关回去。 |
| **Keep panel awake**（保持面板常亮） | 默认关闭：停止触摸三十秒后面板熄灭，熄灭期间不做任何工作。打开后，面板保持点亮。 |
| **Always-on display**（息屏显示） | 默认关闭。打开后，面板以暗淡、静止的状态停留，而不是熄灭，双击会唤出滑块，只有在口袋里才会休眠——参见[当没人在看时](#没人看的时候)。 |
| **↳ clock, battery, date, weather line**（时钟、电池、日期、天气行） | 息屏显示专属的设置：每项都可以在息屏时单独显示或隐藏，随着息屏显示的进入和退出，与时钟页的对应设置相互交接。 |
| **Accounts**（账号） | 一个或两个，每个都有自己的名称、颜色，并可选择浏览器登录或粘贴令牌。 |

每个账号都有**自己的设置页**，从 Usage 标签页上它所在的那一行进入：它在该标签页设置原来的位置滑入，位于同一个预览下方，以玻璃卡片呈现——Connection（连接）、Name & colours（名称与颜色）、Bars（进度条）、Rings（圆环）、Account details（账号详情）——用 Back（返回）或系统返回离开。两个账号就已经让单个界面变成了长长的滚动，而面板本来就打算支持两个以上的账号。

颜色可以在一个**饱和度/亮度方块加色相条**上选择，也可以输入十六进制值，或从面板自己的调色板中选取。每次颜色变化都会在 1.8s 内缓入，与进度条完全一样，在预览和面板上都是如此，所以拖动一个设置时，看起来像是面板在响应，而不是在闪烁。

### 账号属于谁

每个账号的设置可以显示持有人的姓名、邮箱、组织和套餐——足以在你忘了哪个是哪个时区分两个账号。在你用指纹或设备 PIN 码**解锁之前，这些信息是遮盖的**，就像银行应用的做法一样；屏幕锁定、离开该界面或 30 秒后，它会重新隐藏。递给别人的手机，不应该显示这些账号是谁的。

### 从头开始

**ADVANCED → Reset every setting to its default**（高级 → 将所有设置恢复为默认值）会把一切还原。它会先询问，且确认按钮在五秒内保持不可点击——这是应用中唯一一个背后什么都没有、也无法撤销的操作。已连接的账号会保持登录状态。

### 演示模式，仅限调试构建

调试构建多一个开关 **Demo mode**（演示模式），开启后面板会为镜头循环自行表演：依次展示吉祥物的每一种状态，按段驱动进度条及其颜色和重置时间，一个没有响应的账号，扫过音量和播放位置并切换一次曲目，以及十条虚构的通知，戴着手机上实际安装的应用的图标——内容是专门写的而不是借来的，而且故意写得乏味，因为拍摄通知页的全部意义就在于不公开陌生人的消息。滚轮会自己转动。这些都不会出现在发布构建中。
## 面板在别人的手机上熄灭时

有些手机会在最后一次触摸十秒后关闭背屏，不管面板的窗口如何请求——在我的手机上能让它保持亮起的 keep-screen-on 标志，在那些手机上被忽略了。
**Poke the rear display awake**（唤醒背屏）（位于设置中的 Keep panel awake（保持面板常亮）下方）会在面板显示并保持期间，每四秒向背屏发送一次唤醒按键，这在那里算作一次触摸；MiRearScreenSwitcher 依靠的就是这个技巧，只不过它每秒两次。除非你需要，否则保持关闭。

Advanced（高级）→ **Copy rear-display report**（复制背屏报告）会通过 Shizuku 收集系统关于背屏的信息——固件与地区、每个可能占用背屏的软件包以及它是已安装还是被挂起、已注册的背屏启动器组件、背屏相关设置、display 1（背屏）上的窗口，以及电源管理器为它持有的状态——并把这些文本放到剪贴板，同时在屏幕上显示一份。当某人的面板在十秒后变黑而你的没有时，就该向对方要这份报告。

- **有进场和退场的吉祥物状态**，而不是整段循环播放。举重的吉祥物应该戴上一次头带，在你工作期间一直举重，在你停下时摘下头带——而不是每三秒把整段表演从头再来一遍。而且从一个状态到下一个状态的切换，不该再是生硬的硬切。

## 17 Pro Max，以及其他任何背屏

面板按 17 Pro 的背屏（904x572）布局，并缩放到它所在的任何背屏上：17 Pro Max 的背屏是 976x596，面板在那里会铺满整个屏幕。缩放按轴分别进行，因此不会浪费任何边距；在 17 Pro Max 上两个比例相差不到百分之四，没有哪个圆环能看出来。触摸也以同样的方式映射回去。

圆环则是另一回事，因为镜头不会随屏幕缩放。小米自己的背屏应用为每台设备保留一个数值，即镜头列的宽度：17 Pro 上是 104.5dp，17 Pro Max 上是 105.2dp，在背屏的 450dpi 下都约为 296px。所以两款手机上的镜头像素尺寸相同，17 Pro Max 的屏幕只是在镜头周围更宽、更高。因此在 17 Pro Max 上，面板以 17 Pro 的圆环按其像素尺寸为起点，镜头列在更高的屏幕上居中——这个起点取自该应用里的数值，并非在 17 Pro Max 上实测。之后可以在设置 → Ring layout（圆环布局）中调整；如果有一张 17 Pro Max 的截图，就能把默认值设得精确。

哪块屏幕是背屏，是从手机上读取的，而不是写死的。面板通过询问 SurfaceFlinger 来检查自己被绘制在哪里，而 SurfaceFlinger 用物理 id 来命名屏幕，这个 id 原本是写在面板里的：它曾经是 17 Pro 的 id，因此在 17 Pro Max 上，一个正确地待在背面的面板会被判定为滞留在正面。于是每次检查都要把它移到它本来就在的那块屏幕上，系统拒绝，三次拒绝之后面板被结束并重新启动——一遍又一遍，而那块屏幕从未熄灭。现在这个 id 取自 `dumpsys display`，背屏报告会把两份列表都打印出来，所以两者不一致的手机会显示出来。

## HyperOS 检查的背屏策略

在 HyperOS 允许某个 activity 在背屏上启动之前，它会询问该应用是否声明自己为背屏应用：即清单中的 meta-data `miui.rear.policy`，1 表示允许，0 表示不允许（见 miui-services 中的 `ActivityStarterImpl.isShouldShowOnRearDisplay`，它会记录 "allow app" 或 "should not allow app"）。没有这个声明，所有以背屏为目标的启动都会被中止，面板只能先在正面屏幕上启动、之后再移过去——系统重新启动面板时，所谓面板“在正面屏幕上重生”就是这个样子。本应用为整个应用和面板的 activity 都做了声明，并直接在背屏上启动面板。有一个例外来自 HyperOS 本身：锁屏处于锁定状态时，只有它自己名单上的应用可以在那里启动，所以此时面板会先在正面屏幕上启动再被移过去，和以前一样。

## Shizuku，以及为什么不能跳过它

背屏不会接纳一个你直接对着它启动的应用。要把窗口放到那里，需要一次普通应用无权发起的特权调用。**[Shizuku](https://shizuku.rikka.app/)** 就是这座桥：它运行一个带有 shell 级权限的小服务，并把这些权限借给你批准的应用。它不运行，本应用就没有任何办法在你手机背面显示任何东西。

**请注意，它很不稳定。** 它无法自行在重启后存活，某些 ADB 操作会把它搞挂，而它一挂，本应用就根本无法放置面板。

### 启动它

1. 从 [shizuku.rikka.app](https://shizuku.rikka.app/) 或 Play 商店安装 **Shizuku**。
2. 在手机上开启**开发者选项** → **无线调试**（设置 → 关于手机 → 点击 *OS 版本* 七次，然后设置 → 更多设置 → 开发者选项）。
3. 打开 Shizuku，使用**通过无线调试启动**。它会一步步引导你完成配对。
4. 打开本应用。首次运行的列表里有两行与它有关：**Shizuku running**（Shizuku 运行中）会打开 Shizuku 应用（未安装时则打开它的网站），**Allow this app in Shizuku**（在 Shizuku 中授权此应用）会向 Shizuku 请求权限——在弹出的对话框中允许即可。如果 Shizuku 在运行但尚未授权本应用，表现为第二行未勾选，而不是第一行。

**每次重启后，都必须重新启动 Shizuku。** 它自己的通知是最快的回去路径。

如果手边有电脑，`adb shell sh /storage/emulated/0/Android/data/moe.shizuku.privileged.api/start.sh`
可以在不碰手机的情况下重新启动它——在某次 ADB 会话把它弄挂时很有用，而这种事确实会发生。

2. **安装应用。** 从 [Releases 页面](https://gitlab.com/896kb/ai-usage-companion/-/releases) 下载 APK 并安装。

   版本发布由**版本标签**触发，而不是推送到 `main`——见

   ```bash
   ./build-install.sh          # 调试构建，直接安装到已连接的手机
   ```
   调试构建是一个独立的应用，`dev.kb896.aiusage.dev`（“AI Usage (dev)”，图标上带有 dev 标签），所以它会与正式版并存安装，而不是覆盖它。

3. **登录。** 打开应用，可以通过浏览器登录；如果你的账号是受管理的、不便进行设备登录，也可以粘贴令牌。
4. **允许通知。** 没有通知权限，你既会失去用量限制警告，也会失去承载超级岛（HyperIsland）读数的常驻通知——而屏幕上不会有任何东西告诉你原因。

   只有当每个可读取状态的步骤都已满足时，面板才会被放置。在此之前它不会被动——既不会被放到背屏上，也不会每二十秒就跟一个不断把它拿走的系统较劲、再放回去——如果之后某个步骤失效了（小米的应用被恢复、重启后 Shizuku 没了），下一次检查会把面板撤下，而不是去争夺。

   第 4 到第 7 步也列在应用自身设置的顶部，每一项都是一个按钮，会带你去对应的系统界面，完成后自动打勾。全部满足后，列表会折叠成一个 **ONBOARDING**（新手引导）折叠面板，不再碍事——它是入门说明，一整面的勾不该压在你日常回来调整的设置上方。如果之后某项权限被撤销，或者重启后没有重新启动 Shizuku，它会重新展开。
5. **把小米自己的背屏应用挪开。** HyperOS 的 `com.xiaomi.subscreencenter` 想占用同一块屏幕，系统会不断把它自己的界面重新放到面板之上；只有把它移除，面板才能待住。新手引导列表里有一行专门处理它：**Remove Xiaomi's rear-screen app**（移除小米背屏应用）会先询问，然后通过 Shizuku 执行 `pm uninstall -k --user 0`——这只是对你的用户隐藏该应用，不删除任何东西，它仍保留在系统分区上。之后同一行会变成 **Restore Xiaomi's rear-screen app**（恢复小米背屏应用），随时一键用 `pm install-existing` 撤销——并解除早先某个变通办法留下的挂起状态（被挂起的应用恢复后虽然存在，却不被允许运行，看起来就和一次什么也没做的恢复一模一样）。
6. **为本应用关闭 HyperOS 省电限制**，并允许后台活动。HyperOS 在这方面很激进：开启限制时它会停止轮询服务，面板就冻结在最后一次读数上——把过时的数字显示得像是最新的。
7. **授予通知使用权**——仅当你想把其他应用的通知镜像到面板上，或想使用媒体控制时才需要。两者都依赖这一项授权；播放器没有单独的开关，因为 Android 会把当前活跃的媒体会话交给持有通知使用权的应用。没有它，这两项功能都不起作用，其他一切照常工作。新手引导列表里有一个按钮，而且与自启动不同，这一步能读取自身状态，所以授权后会自动打勾。
8. **允许自启动。** 否则 HyperOS 不会让应用自行启动——重启后不会，被系统杀掉后也不会。这是决定面板会自己回来、还是等你打开应用的唯一设置，也是这台手机上每个常驻应用都需要的那一项。新手引导列表里有对应的按钮；它位于 安全 → 权限 → 自启动。

   它的状态任何应用都无法读取——MIUI 没有为它提供任何权限、设置项或 dumpsys 字段——所以这一步以建议加按钮的形式显示，而不是一个能自动打勾的项目。
9. **在最近任务中锁定应用。** 打开最近任务，长按本应用并锁定。否则“全部清除”会把它清掉，从而杀掉轮询服务，连带面板一起撤下。这是建议而非必需，但它决定了面板是撑过你的一整天，还是死于一次下意识的操作。这是唯一一个应用无法替你检查的步骤——HyperOS 不公开应用是否被锁定——所以它以建议的形式显示，而不是一个永远勾不上的框。
10. **让应用转入后台。** 面板会自行放置并待在那里——服务启动时会把它放到背屏上，如果有任何东西把它拿走，看门狗会把它放回去，手机休眠时也是如此。点击通知仍然可以手动重新放置它，这是唯一一条不需要打开应用的恢复途径，但它已不再是任何人必须执行的步骤。

**应用必须保持在后台运行。** 面板由本应用绘制；没有别的东西会替你渲染它。如果应用被杀掉，背面就会一直黑着，直到你再次打开它。
## 保持运行

面板要撑过一整天，有三件互不相关的事必须同时成立，而其中任何一件不成立都足以致命。

**前台服务的类型是 `specialUse`，而不是 `dataSync`。** 从 Android 15 起，`dataSync` 前台服务**在任意 24 小时内最多运行六小时**，超出后系统就会将其停止——而本应用的 targetSdk 是 36。这个上限描述的恰恰是同步任务，与这个服务毫不相干：它并不按计划搬运数据，而是在手机开机期间一直维持第二块屏幕的运行。服务被停止时，面板也随之消失，而设备上没有任何地方说明原因。

**必须授予 HyperOS 自启动权限**，否则系统不允许应用在重启后或被杀掉后自行启动。这台手机上每个常驻应用都需要这项设置。它的状态没有任何途径可以读取——`dumpsys package` 不行，`appops` 不行，`settings` 也不行——所以引导流程里这一步是一个不带勾选标记的按钮，原因就在于此。

**看门狗现在在手机休眠时也能工作。** 它以前会拒绝工作，而且拒绝得没错：面板 activity 必然先在主屏（MAIN display）上创建，然后才移到背屏，而它带着一个 turn-screen-on 标志，所以手机休眠时的每一次重启都会把手机唤醒。这个标志已经去掉了——改为由特权服务显式唤醒背屏，它可以只针对某一块屏幕，而窗口标志做不到这一点。两种方式都测量过：之前是 `Dozing → Awake`，之后是 `Dozing → Dozing`，面板仍然会落在背屏上。

正是最后这一条，修好了「双击背屏熄屏再点亮，却发现上面什么都没有」的问题。面板已经死了，而代码决定不去看。

**面板可能活着却不可见，而这在以前是无法检测的。** 每一项健康检查回答的都是「我们的图层是否正在背屏上被合成」，答案有三种：是；否，它在主屏上；以及*哪里都没有*。第三种答案其实是两件不同的事共用了一个名字——一种是面板休眠，这很正常，绝不能对此采取行动；另一种是 HyperOS 自己的背屏启动器占用了这块屏幕，而我们的任务待在它后面，活着却什么也不画。保活的恢复分支要求「哪里都没有合成**并且**没有任务」，而在第二种情况下，任务恰恰还在。所以它从未触发。这是在设备上当场抓到的：背屏显示着时钟加步数小组件，activity 在后台处于暂停状态，服务在运行，而每一项检查都报告一切健康。

区分两者的依据是背屏**还**在合成什么别的东西。一块正在显示其他应用图层的屏幕是亮着的，只是显示的不是我们；一块什么都没在合成的屏幕则是在休眠。这现在是第四种状态，它的恢复方式是完整地重新放置，而不是移动——任务已经在正确的屏幕上了，只是不在最上层，而把任务移到它本来就在的屏幕上并不会把它提到前面。

检查现在也改为每 **6 秒**运行一次，而不是每 20 秒。一次检查就是一次 `dumpsys SurfaceFlinger`，在这台设备上测得耗时 40ms，所以开销远低于单个核心的百分之一——而且旧代码在某些分支里每次检查要调用两次，现在只调用一次。端到端测量的方法是故意在面板上方启动 HyperOS 的启动器：+3s 时面板消失，+9s 前恢复，而改动之前同样的测试需要 16 到 28 秒。

重建每 15 秒最多一次。这是防止互相争抢的保险，而不是在正常路径上加的延迟：单次被占用会在紧接着的下一次检查时恢复，但如果系统反复把自己的启动器提到前面，每次检查都重新放置就会变成一场肉眼可见的拉锯战。它不会就此放弃——面板本就应该在那里，只要应用还在运行，它就会一直争取。

## 工作原理

背屏拒绝承载直接在其上启动的 activity。因此应用先在主屏上启动面板，再请求以 shell 身份运行的 Shizuku 把这个任务移过去：

```
am start …                 在 display 0 上启动
am display move-stack …    把任务移到背屏
input -d 1 keyevent WAKEUP 唤醒面板
```

第二条命令以前是一个原始的 binder 事务编号。不要改回去：事务编号取决于方法在 AIDL 中的位置，而 Android 16 挪动了这一个，此后这个调用一直报告成功，实际上却什么都没做。

面板运行在它自己的 `:rear` 进程中，系统会不停地销毁并重建这个进程。它不保存任何状态——它绘制的所有内容都通过同一个数据包送达，所以重启后的面板绝不会有片刻显示错误。

这块屏幕常亮且没有空闲超时，对 OLED 来说这几乎是最容易烧屏的情形。整个画面以十分钟为周期漂移 ±4px，而圆环——必须与镜头保持同心——则改为让半径伸缩 ±3px。这是承担实际作用的，不是装饰。

每个吉祥物都是一组矩形而不是图片，而且全部画在同一套网格上：一个美术像素等于 11 个单位，一只眼睛恰好是一个像素。正是这个共享的单位，才让各个姿态之间能相互比对尺寸——每个动画片段都以这个单位声明自身边框的高度，绘制时的缩放比例由此推出，所以「和其他的一样大」是算出来的，而不是有人凭肉眼调出来的数字。在把这一点写成构建可以检查的规则之前，其中两个已经分别偏离了 43% 和 15%。

这也意味着一个动画片段可以为它甩到角色之外的东西预留空间——彩纸屑、一面旗子、睡着的脑袋上方的 Z——而不必让角色缩小来腾出地方。

## 署名

吉祥物是 **Anthropic 的 Claude 吉祥物**。动画提取自 [ayotomcs.me/claude-mascot](https://ayotomcs.me/claude-mascot)，并重建为像素数据；其中行走动画则是对其 GSAP 时间轴的重新实现。面板上的制作者标记属于 **ACRNM**。两者都不是我的作品，也都不受本仓库许可证的约束——收录它们是为了忠实还原面板所依据的设计。如果你拥有其中任何一项，并且不希望它们出现在这里，请提一个 issue，我会将其移除。

字体方面，ORIGINAL 使用 Helena Zhang 设计的 [Departure Mono](https://departuremono.com/)，GLASS 使用 Smartsheet 的 [Outfit](https://github.com/Outfitio/Outfit-Fonts)——两者均采用 SIL Open Font License 1.1。

GLASS 基于 Kyant0 的 [AndroidLiquidGlass](https://github.com/Kyant0/AndroidLiquidGlass)，Apache 2.0。它的 AGSL 代码是直接复制（vendored）进本仓库的，而非作为依赖引入——该库是为 Compose 编写的，而这里直接在 Canvas 上使用这些着色器——许可声明也一并保留在旁边。正面屏幕上的玻璃控件——`ui/glass/` 下的卡片、开关、分段选择、按钮、滑块和对话框面板——移植自该库示例应用（catalog app）中的组件，并用 View 重建；每个文件都注明了它来自哪个示例应用文件。GLASS 的图标是 **Material Symbols Rounded**，正面屏幕的图标是 **Material Icons**，两者均为 Apache 2.0，来自 [material-design-icons](https://github.com/google/material-design-icons)。ORIGINAL 的图标是从 Nerd Fonts 描摹成像素矩形的，而非直接打包。

雪景改编自 [Godot Shaders](https://godotshaders.com/shader/multilayer-snowfall-shader/) 上 **Lumine 的多层降雪着色器（multilayer snowfall）**，CC0——属于公有领域，所以无需承担任何义务，但仍值得说明它的出处。雨景是本仓库自己的作品。

天气数据由 [Open-Meteo](https://open-meteo.com/) 提供（CC BY 4.0）。

唱片是一张图库照片，裁剪到只剩唱片盘面，并把中间的标签抹平了——专辑封面总会盖住那一部分，而如果下面是一枚橙色标签，面板上的每一张封面都会被染上颜色。
